BountyPilot HSP
Verify the work, then pay for it.

AI agents are starting to buy compute from each other. Today the buyer's agent pays on trust: the provider says "done" and the money moves. BountyPilot HSP is the buyer-side payment agent that checks the delivery itself - and only releases payment when the work passes the buyer's own acceptance tests.

Demo (50 seconds)

Interactive demo: verify the sample job result in your browser and watch the agent's simulated verify-before-pay payment decision.

A real transcode job is delivered and verified, then a tampered delivery is refused. The payment shown is a simulated settlement against a mock server that enforces the documented HSP contract - no real funds moved. This website is a demo page: the video and the story. The product itself runs locally from the repository - there is no hosted compute service to try.

How it works

Agree the job. Buyer and provider agents fix the work and its acceptance conditions: format, duration, codec, plus any custom test script the buyer wants.

Provider delivers. The compute provider runs the job and hands over the artifact.

Buyer verifies the delivery itself. Our agent executes the acceptance checks on the artifact - not on the provider's word.

Only on PASS, pay. The payment agent builds the HSP Payment Mandate and EIP-712-signs it (a generated development key in this demo; the human confirmation gates that would approve a real wallet signature are implemented and shown auto-approved), then submits through the HSP gateway flow. On FAIL, no payment order is ever created.

What this build proves - and what it does not

Real in this repo

  • Compute job: ffmpeg transcode runs for real in the demo
  • Verification: buyer-owned acceptance suite executes on the delivered file (ffprobe + custom tests)
  • EIP-712 mandate signing: real keccak/secp256k1 cryptography
  • HSP flow per the official guide: order, prepare, confirm gates, sign, finalize, submit, quote-expiry re-sign, status recovery, team attribution
  • Test suite: 53/53 passing, runs in about a second

Not yet

  • Live HSP QA execution: organiser IP allowlisting and a 403 access issue are both unresolved; the demo settles against a mock enforcing the documented contract
  • Provenance, compute metering, creditworthiness: out of scope for the verifier today
  • Lending, staking, credit issuance: not claimed - that is the roadmap, not this build

Why it matters

Compute marketplaces between agents - and any future compute-credit layer - need an answer to one question before money moves: did the buyer actually get what it paid for? This repo is that evidence-and-settlement layer, built on HashKey's HSP.

Status at submission: local prototype. Live HSP QA had not been demonstrated; organiser allowlisting and a 403 access issue were unresolved. No mainnet or testnet deployment of custom contracts is required by this design - settlement goes through HSP's gateway.
